# نظام التقارير التفتيشية

نظام لإدخال بيانات **الزيارة التفتيشية وزيارات المتابعة** وتصدير تقرير **Word (.docx)** بقالب رسمي.

يعمل على **الحاسوب والهاتف**، و**بلا إنترنت**، وبلا خادم أو قاعدة بيانات.

---

## ما الذي يفعله

| المرحلة | الوصف |
|---|---|
| **إدخال البيانات** | نموذج عربي كامل للجانب **الإداري** فقط: بيانات المؤسسة، المسؤولون، الملاك، وحدة البصمة، الإجراءات، الملاحظات العامة، مواقف البصمة، السجلات الإدارية، التوصيات، التوقيعات |
| **نطاق التقرير** | تختار: **البصمة والسجلات** معاً، أو **البصمة فقط**، أو **السجلات فقط** — وتُخفى الأقسام غير المختارة |
| **قوائم قابلة للتعديل** | **كل** قائمة منسدلة وحقل اقتراح في الموقع (العناوين الوظيفية، الصفات، فئات الملاك، أنواع الإجراءات، أنواع المواقف، حالات التوصيات، أسماء السجلات، أنواع الزيارة، أنواع المؤسسات، دوريات وجهات رفع الموقف) تُحرَّر من «مكتبة العبارات» — بلا كود |
| **مكتبة عبارات** | تقييمات جاهزة للسجلات وتوصيات متكررة مستخرجة من التقارير السابقة، بإملاء مصحّح |
| **معاينة** | عرض التقرير بشكل مطابق لملف Word قبل التصدير |
| **تصدير Word** | ملف `.docx` حقيقي بمقاس A4، اتجاه RTL، ترويسة رسمية، **فقرات فقط بلا أي جدول**، وترقيم صفحات |
| **الأرشيف** | حفظ واسترجاع وبحث، وتصدير/استيراد نسخة احتياطية بصيغة JSON |
| **المزامنة** | اختيارية — لمشاركة التقارير بين هاتفك وحاسوبك |

### ملاحظات على البنية

- **تقرير جديد:** زر «تقرير جديد» يسأل أولاً: أحفظ التقرير الحالي في الأرشيف أم لا؟
  ثم يفتح نافذة إدخال **فارغة تماماً** — لا صفوف إجراءات ولا توقيعات مُنشأة مسبقاً.
  إن كان التقرير الحالي فارغاً فلا سؤال، ويبدأ الجديد مباشرة.
- **عدد النفوس والعوائل المسجلة:** حقول في نافذة الإدخال **أسفل** جدول الملاك،
  وتظهر في التقرير في نهاية قسم «الملاك الكلي والفعلي».
- **جهة السحب / المصدر:** حقل باقتراحات، تُحرَّر قائمتها من **مكتبة العبارات**
  (قائمة «جهات السحب / المصادر»).
- **زر «نسخ النص كاملاً»:** في نافذة المعاينة بجانب «تصدير Word» — ينسخ التقرير
  بتنسيقه (عناوين وعريض وقوائم) لتلصقه في البريد أو Word.
- **عرض الهاتف:** جداول الإدخال تتحول تلقائياً إلى **بطاقات** — كل حقل يأخذ سطراً كاملاً
  وبعنوانه فوقه. لا سحب أفقي إطلاقاً، وحقول كبيرة مريحة للمس (46 بكسل ارتفاعاً و16 بكسل خطاً).
  جداول سطح المكتب والطباعة تبقى كما هي.
- الجانبان **الفني والهندسي غير مشمولين** — النظام للجانب الإداري فقط.
- ملف Word الناتج **لا يحتوي أي جدول**: كل البيانات (الملاك، السجلات، متابعة التوصيات) تُصاغ فقرات نصية.
- عنوان التقرير **يُولَّد تلقائياً** من نوع الزيارة + نوع المؤسسة + اسم المؤسسة + الجهة التابعة،
  ويتحدّث فور تغيير أي منها. وإن كتبته بيدك يحترم النظام كتابتك ولا يستبدلها.
- **كل قائمة اختيار قابلة للتعديل** من «مكتبة العبارات» ← «قوائم الاختيار»: أضف قيمة،
  احذف، أعِد الترتيب (أعلى/أسفل)، أو أرجع القائمة لأصلها. التعديل ينعكس **فوراً** على النماذج.
  لا يوجد خيار مقيّد في الكود.
- الملاك يحتوي سبع فئات جاهزة (قابلة للتعديل): الملاك، الأطباء، أطباء الأسنان، الصيادلة، تقني طبي، ممرضين، إداريين.
- كل سجل إداري يقبل **أكثر من تقييم جاهز** بنقرة، **بالإضافة** إلى تقييم تكتبه بيدك، ويُدمجان معاً.
- فئات المخالفة في مواقف البصمة كلها بثلاثة حقول: العنوان الوظيفي، الاسم الثلاثي، ملاحظة.
  وإضافة فئة جديدة تنشئ فئة ثالثة بنفس الحقول تلقائياً.
- إضافة العبارات من المكتبة **تُلحق ولا تستبدل**: يمكنك تحديد عدة عبارات وإضافتها دفعةً واحدة،
  ثم إضافة غيرها لاحقاً وتبقى كلها.

**تحذير مهم:** تعديلات القوائم محفوظة في متصفح الجهاز. إن أردت استخدامها على هاتفك
فاستخدم «تصدير القوائم» ثم «استيراد القوائم» هناك، أو فعّل المزامنة (تنتقل تلقائياً).


## النشر على Cloudflare Pages

### 1) ارفع المشروع إلى مستودع GitHub **خاص**

```bash
git init
git add .
git commit -m "نظام التقارير التفتيشية"
git branch -M main
git remote add origin https://github.com/<حسابك>/<المستودع>.git
git push -u origin main
```

### 2) اربط المستودع بـ Cloudflare Pages

1. سجّل الدخول إلى <https://dash.cloudflare.com> ← **Workers & Pages** ← **Create** ← **Pages** ← **Connect to Git**.
2. اختر المستودع الخاص. ستحتاج إلى منح Cloudflare صلاحية الوصول إلى مستودعاتك الخاصة.
3. إعدادات البناء:
   - **Framework preset**: `None`
   - **Build command**: *(اتركه فارغاً)*
   - **Build output directory**: `/`
4. اضغط **Save and Deploy**.

سيصبح الرابط بالشكل: `https://<اسم-المشروع>.pages.dev`

### 3) حماية الوصول (مهم)

الرابط عام افتراضياً. لتقييده على موظفي الدائرة:

**Cloudflare Access** ← **Zero Trust** ← **Access** ← **Applications** ← أضف تطبيقاً من نوع *Self-hosted*، وحدّد:
- النطاق: `اسم-المشروع.pages.dev`
- السياسة: البريد الإلكتروني للعاملين المصرّح لهم (OTP عبر البريد) أو نطاق بريد الدائرة.

هذا يمنع أي شخص خارج القائمة من فتح الموقع أصلاً.

### 4) ملاحظة على الخصوصية

الموقع **ثابت بالكامل**. لا يوجد خادم يستقبل البيانات، ولا قاعدة بيانات، ولا إرسال لأي معلومة.
كل بيانات التقارير تُخزَّن في متصفح المستخدم فقط (`localStorage`)، ولا تُرفع إلى Cloudflare إطلاقاً.

لذلك حتى مع استضافة مجانية، لا توجد بيانات موظفين على أي خادم خارجي.

**القيد المترتب على ذلك:** البيانات لا تتزامن بين الهاتف والحاسوب تلقائياً. للنقل بينهما استخدم
«تصدير كل الأرشيف (JSON)» ثم «استيراد» في الجهاز الآخر.

## التحقق بعد النشر

افتح `https://<موقعك>/check.html` — صفحة فحص تتحقق من:

1. **تشغيل النظام**: البروتوكول، التخزين المحلي، عامل الخدمة (العمل بلا إنترنت).
2. **المزامنة السحابية**: اضغط «الدخول بحساب Google»، وتختبر الصفحة الدخول وقراءة/كتابة
   Firestore فعلياً، وتخبرك بالسبب الدقيق إن فشلت — مع الخطوة المطلوبة في لوحة Firebase.

### الأخطاء الشائعة وحلولها

> **الدخول بحساب Google فقط.** لا كلمات مرور في النظام — أُزيل البريد وكلمة المرور
> بطلب صريح. استخدم **نفس حساب Google** على كل أجهزتك.

> **قبل كل شيء:** نطاق Cloudflare قد يكون *.pages.dev أو ***.workers.dev** أو نطاقاً
> مخصصاً. **العبرة بالنطاق المكتوب في شريط العنوان.** افتح صفحة **الفحص** (/check.html)
> وانسخ «النطاق الحالي» منها حرفياً.

| ما تراه | السبب | الحل |
|---|---|---|
| **«هذا النطاق غير مصرّح به»** (`auth/unauthorized-domain`) | نطاقك غير مسجَّل في Firebase. المسجَّل تلقائياً هو `localhost` و`*.firebaseapp.com` فقط | **Authentication** ← **Settings** ← **Authorized domains** ← **Add domain**، والصق النطاق كما يظهر في صفحة الفحص — **بلا `https://` وبلا أي مسار بعده** |
| **«العملية مطلوبة غير مُفعَّلة»** (`auth/admin-restricted-operation`) | الدخول بحساب Google غير مُفعَّل | **Authentication** ← **Sign-in method** ← فعّل **Google** |
| **«خطأ داخلي من Firebase»** (`auth/internal-error`) | المتصفح لا يدعم نوافذ الدخول — تطبيق مضمّن أو نافذة تصفّح خاص | افتح الموقع في **Chrome** مباشرةً. عند فشل النافذة ينتقل النظام تلقائياً إلى إعادة التوجيه |
| **الدخول لا يكتمل على الهاتف بينما يعمل على الحاسوب** | الأسباب مرتّبة بالاحتمال أدناه | ① تأكد أن **Google مُفعَّل** في **Sign-in method**. ② أضف نطاقك في **Authorized domains**. ③ امسح ذاكرة المتصفح لموقعك (النسخة القديمة تُخدَم من الذاكرة). ④ افتح الموقع في Chrome لا من الأيقونة المثبَّتة |
| **«لم تكتمل إعادة التوجيه»** | عُدت من Google ولم تُقرأ الجلسة | افتح الموقع في Chrome مباشرةً، وتأكد أن الكوكيز مسموحة |
| **الدخول يفشل داخل التطبيق المثبَّت** | التطبيقات المثبَّتة على الهاتف تُقيّد نوافذ Google | افتح الموقع في **Chrome مرة واحدة** وسجّل الدخول، ثم افتح التطبيق المثبَّت وستجد الجلسة محفوظة |
| «رفض الخادم العملية — قواعد أمان Firestore» | القواعد غير منشورة | **Firestore Database** ← **Rules** ← الصق القواعد أدناه ← **Publish** |
| «قاعدة بيانات Firestore غير موجودة» | لم تُنشئ القاعدة | **Build** ← **Firestore Database** ← **Create database** |
| صفحة «جارٍ التحقق» من Cloudflare تظهر دائماً | Access لا يتذكّر الجلسة | تأكد من إعداد سياسة Access، وأن المتصفح يسمح بالكوكيز |
| التعديلات لا تظهر على الموقع | Cloudflare لم يُعِد البناء | Pages ← آخر نشر ← **Retry deployment** |

### قائمة تحقق سريعة (٣ خطوات)

1. **Authentication** ← **Sign-in method** ← فعّل **Google**.
2. **Authentication** ← **Settings** ← **Authorized domains** ← أضف نطاقك حرفياً.
3. **Firestore Database** موجودة و**Rules** منشورة — ثم افتح صفحة **الفحص**.

> **كيف يعمل الدخول:** يُجرَّب **فتح نافذة Google** أولاً (يعمل في Chrome على الهاتف).
> وإن فشلت — كما يحدث داخل التطبيق المثبَّت — ينتقل النظام تلقائياً إلى إعادة التوجيه،
> ثم ينتظر **الجلسة المحفوظة** عند العودة. وهذا أهم من نتيجة إعادة التوجيه نفسها.

### ملاحظة مهمة على الخصوصية مع Zero Trust

لا تُدخل **الموظفين المُفتَّش عليهم** في سياسة Access إلا إذا كان ذلك مقصوداً — فمن يملك بريداً
في القائمة يستطيع فتح النظام وإدخال تقارير. اجعل القائمة على قدر من يحتاج الإدخال فعلاً.

وقواعد Firestore أدناه تعزل بيانات كل مستخدم بحسب `uid`، فلا يرى أحد تقارير غيره
حتى داخل نفس النظام.

## تعديل القوائم وتثبيتها

**مكتبة العبارات** ← **قوائم الاختيار**: ١٧ قائمة قابلة للتعديل (العناوين الوظيفية، الصفات،
فئات الملاك، فئات المخالفة، أنواع الإجراءات والمواقف، حالات التوصيات، أسماء السجلات،
جهات التوصيات وحروفها، أنواع الزيارة والمؤسسات، دوريات وجهات رفع الموقف...).

لكل قيمة: إضافة · حذف · ترتيب (أعلى/أسفل) · إرجاع القائمة للأصل.

### هل تريد أن تنتقل تعديلاتك إلى كل الأجهزة؟

حالتان مختلفتان، اختر ما يناسبك:

| الطريقة | متى تستخدمها | كيف |
|---|---|---|
| **تصدير/استيراد JSON** | نقل سريع بين أجهزتك أنت | زر «تصدير القوائم» هنا، و«استيراد» على الجهاز الآخر |
| **حفظ القيم كأصل** | تثبيت التعديل دائماً في المشروع لكل من يستخدم النظام | زر **«حفظ القيم كأصل»** ← يُنزَّل `options.js` جديد ← ضعه مكان القديم ← `git commit` و `git push` |
| **المزامنة السحابية** | إن فعّلت المزامنة | القوائم تنتقل تلقائياً مع التقارير والإعدادات |

### لماذا «تنزيل ملف» ولا كتابة مباشرة؟

المتصفح **لا يستطيع** الكتابة على القرص (عبر `file://`) ولا على خادم الاستضافة
(عبر `https`). هذه حماية مفروضة على كل المتصفحات ولا سبيل برمجياً لتجاوزها.
لذلك يُنزَّل الملف الجديد لترفعه بنفسك — مرة واحدة، فيصل التعديل إلى كل الأجهزة.

بعد الرفع، كل جهاز يفتح التطبيق يقرأ القيم الجديدة كأصل. وإن عدّل أحدهم من الواجهة
فالتعديل يبقى على جهازه فقط حتى يعيد «حفظ القيم كأصل» أو يستخدم المزامنة.

> **نصيحة:** إذا كنت تعمل وحدك، فعّل المزامنة السحابية لتنتقل القوائم وحدها
> بلا أي رفع ملفات.

### إصلاح دخول الهاتف: Google Identity Services

**المشكلة:** إعادة توجيه Firebase تعتمد على **تخزين الطرف الثالث** بين نطاقك و
`firebaseapp.com`. وكروم على أندرويد **يحجبه افتراضياً**، فتُكمل Google الدخول
ويرجعك الموقع **بلا جلسة** — بلا أي رسالة. ونفس السبب يمنع النافذة المنبثقة.

**الحل:** **Google Identity Services** — يعمل من نطاقك مباشرةً ويعيد رمز الهوية،
ثم نحوّله إلى جلسة Firebase. **بلا تخزين طرف ثالث إطلاقاً.**

> **معرّف عميل Google مضمَّن في `sync.js`** — لا حاجة لإدخاله يدوياً.
> وهو معرّف **عام بطبيعته** (يُرسل إلى المتصفح في كل الأحوال، تماماً مثل مفاتيح
> Firebase أعلاه)، والحماية الفعلية تأتي من `Authorized JavaScript origins`
> ومن قواعد أمان Firestore. **ولا حاجة لـ Client Secret إطلاقاً.**

#### ما يجب أن يكون في Google Cloud Console (مرة واحدة)

1. مشروع **`admh-inspection-reporting-sys`** — نفسه المستخدم في Firebase.
2. **APIs & Services** ← **Credentials** ← **OAuth client ID** ← نوع **Web application**.
3. **Authorized JavaScript origins** يقبل النطاق **بالبروتوكول وبلا مسار**:
   ```
   https://admh-inspection-reporting-system.ahmdze.workers.dev
   ```
4. انسخ **Client ID** — وهو مضمَّن في `sync.js` في الحقل `googleClientId`.

#### كيف تتحقق أن كل شيء يعمل؟

افتح `/check.html` واقرأ:
```
✓ معرّف عميل Google — مضبوط — مضمَّن في النظام
✓ Google يقبل هذا النطاق — مكتبة Google مهيّأة والنطاق مقبول
```

> **الفحص حقيقي:** يُهيّئ مكتبة Google فعلاً وينتظر ردّها. ولا يعتمد على نداء
> `/gsi/status` — فذلك النداء يُعيد **400** بلا معاملات، وكان يُعطي
> **إنذاراً كاذباً** رغم إعداد سليم.

#### لماذا لا تظهر النافذة على الهاتف؟ (مُعالَج)

كان الطلب يبدأ **بعد** انتظار تحميل المكتبتين، فيضيع **تفعيل نقرة المستخدم**،
فيحوّل Chrome النافذة إلى **إعادة توجيه كاملة** — وهذا ما كان يحدث على الهاتف:
نافذة تُفتح ثم انتقال إلى Google ثم رجوع بلا جلسة.

**الحل المُطبَّق:**

1. **تجهيز مسبق** عند فتح شاشة الإعدادات (`prepareGoogle`): تُحمَّل Firebase
   ومكتبة Google ويُبنى عميل الرمز **قبل** أن يضغط المستخدم.
2. **الطلب فوري في نفس المهمة** (`startGisRequest`): يُسند النداء ويُطلب الرمز
   بلا أي انتظار وعد — فيبقى داخل تفعيل النقرة، **فتظهر نافذة لا انتقال**.
3. إن لم يكتمل التجهيز عند النقر، يُخبرك النظام:
   **«جارٍ تجهيز الدخول من Google… اضغط الزر مرة أخرى»** ثم تعمل النقرة الثانية
   فوراً. وهذا أفضل من محاولة تفشل بصمت.

#### «لم يُعِد Google رمز الهوية» — **مُعالَج نهائياً**

**ما كان يحدث:** نافذة Google تظهر وتختار حسابك، ويصل **`access_token`** بلا
**`id_token`** — وهذا هو الشائع في مسار الرمز (token client).

**لماذا كانت المشكلة؟** كان الكود يطلب `id_token` **فقط**، ويرفض الدخول إن غاب.
وكان ذلك خطأً، لأن **Firebase يقبل كليهما**. نصّ توثيقه الرسمي:

> Creates a credential for Google. **At least one of ID token and access token is required.**
> `GoogleAuthProvider.credential(idToken?, accessToken?)`

**الحل المُطبّق:**
```javascript
const cred = provider.credential(idToken || null, accessToken || null);
```
فإن غاب رمز الهوية ووصل رمز الوصول، يُنشأ **Credential من رمز الوصول** وتكتمل
الجلسة عادةً.

**التغييرات المرافقة:**
- **FedCM مفعّل** (`use_fedcm_for_prompt: true`) — لتجاوز حجب كوكيز الطرف الثالث.
- **لا نافذة ثانية:** إن نجح رمز الوصول، لا يُفتح مسار Firebase إطلاقاً.
- **رسالة أدق** عند غياب الرمزين معاً (وهو نادر).
- **تشخيص أوضح:** صفحة الفحص تعرض **«آخر استجابة من Google»** لتبيّن ما وصل فعلاً.

**إن أردت تغيير المعرّف:** **الإعدادات** ← **☁️ المزامنة السحابية** ←
**⚙️ معرّف عميل Google** ← الصق ← **حفظ المعرّف**.

- القسم **ظاهر دائماً** في بطاقة المزامنة (سواء كنت متصلاً أم لا).
- الحقل **باتجاه LTR** — لأن المعرّف نصّ لاتيني داخل صفحة عربية، وبدون ذلك
  تبدو الأرقام في آخر السطر بسبب الشارحة `-` (تشويه بصري فقط).
- زر **«📋 لصق من الحافظة»** يُنظّف القيمة من المسافات ومحارف الاتجاه المخفية.
- وسطر **«المحفوظ: …»** يعرض المعرّف كما حُفظ فعلاً لتتأكد أن الأرقام في أولها.

وإن فشل مسار Google Identity لأي سبب، ينتقل النظام **تلقائياً** إلى مسار
Firebase المعتاد — فلا يتعطّل شيء.

## المزامنة السحابية (اختيارية)

لجعل التقارير تظهر على **الهاتف والحاسوب معاً**. التطبيق يعمل كاملاً بدونها.

### خطوات الإعداد (مرة واحدة فقط)

إعدادات Firebase **مضمّنة في الكود** (sync.js)، فلا تحتاج لصق أي مفاتيح.
يكفي تهيئة المشروع مرة واحدة:

1. افتح <https://console.firebase.google.com> واختر مشروعك
   admh-inspection-reporting-sys.
2. **Build** ← **Authentication** ← **Get started** ← **Sign-in method** ← فعّل **Google**.
3. **Build** ← **Firestore Database** ← **Create database**
   - اختر **Production mode**
   - اختر أقرب موقع جغرافي: me-west1 (أوروبا الغربية) هو الأقرب للعراق.
4. من تبويب **Rules** الصق القواعد أدناه ثم اضغط **Publish**. **هذه الخطوة إلزامية.**
5. في التطبيق: **الإعدادات** ← **المزامنة السحابية** ← **الدخول بحساب Google**.

كرّر الخطوة 5 على الجهاز الآخر **بنفس حساب Google**، وستظهر التقارير تلقائياً.
إن لم يكن الحساب موجوداً سيُنشأ تلقائياً عند أول دخول.

> **بخصوص نطاقات النشر:** `localhost` و`*.firebaseapp.com` مضافان تلقائياً في Firebase.
> أما نطاق Cloudflare (`*.pages.dev` أو **`*.workers.dev`** أو نطاقك المخصص) **فيجب إضافته
> يدوياً** في **Authentication** ← **Settings** ← **Authorized domains**. صفحة
> `/check.html` تعرض نطاقك الحالي جاهزاً للنسخ.

### قواعد أمان Firestore (إلزامية)

الصقها كما هي. تمنع أي مستخدم من رؤية بيانات غيره:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
    // لا وصول لأي مسار آخر
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

### كيف تعمل المزامنة؟

| السلوك | التفصيل |
|---|---|
| **الاتجاه** | ثنائي: سحب ← دمج ← دفع. كل جهاز يرى تعديلات الآخرين. |
| **التعارض** | الأحدث يفوز بحسب `updatedAt`. التعديل الأقدم لا يطمس الأحدث. |
| **الحذف** | يُعلَّم السجل بـ«شاهد قبر» بدل حذفه فوراً، لينتشر الحذف إلى بقية الأجهزة. |
| **العمل بلا إنترنت** | كل شيء يُحفظ محلياً أولاً. عند عودة الاتصال اضغط «مزامنة الآن». |
| **الخصوصية** | كل البيانات في `users/{uid}/...` — لا يرى أحد بيانات غيره. القواعد تفرض ذلك على الخادم لا في التطبيق فقط. |
| **ما يُزامَن** | التقارير + الإعدادات (الترويسة والخط) + مكتبة العبارات. |

### تنبيهات مهمة

- **الخطوة الرابعة (Rules) ليست اختيارية.** بدونها إما تُرفض كل العمليات أو — إن
  تُركت في وضع الاختبار — تصبح بياناتك مكشوفة لأي شخص يملك رابط المشروع.
- التطبيق لا يُحمّل أي سكربت خارجي إلا بعد ضغطك «تفعيل المزامنة».
- عمل مشروع Firebase لا يعني أن وزارة الصحة وافقت على تخزين بيانات الموظفين على
  خوادم Google. راجع جهتك قبل إدخال بيانات حقيقية.
- الرابط العام للموقع محمي بـ Cloudflare Access، لكن Firebase مشروع منفصل وله
  ضبطه الأمني الخاص (القواعد + Authorized domains).

### ملفات منطق التقرير (مستقلة لسهولة التحرير)

نُقل منطق التقرير من `app.js` إلى خمسة ملفات مستقلة. كل ملف مملوء بتعليقات
عربية تشرح **كل أمر**، لتعدّله بثقة:

| الملف | وظيفته | عدّله إذا أردت تغيير |
|---|---|---|
| `report-model.js` | يبني «نموذج بيانات» منظّم من النموذج | ترتيب الأقسام، صياغة العناوين، أي بيانات تدخل التقرير |
| `report-preview.js` | يحوّل النموذج إلى HTML للمعاينة | شكل المعاينة على الشاشة: العناوين، القوائم، الفواصل |
| `report-clipboard.js` | ينسخ التقرير بتنسيقه إلى الحافظة | صيغة النص المنسوخ |
| `report-word.js` | يولّد ملف Word (.docx) | الخط، الأحجام، الهوامش، تباعد الأسطر |
| `report-print.js` | يطبع التقرير من إطار خفي | شكل الورقة المطبوعة: الهوامش، الخط، اتجاه الصفحة |

**ترتيب التحميل مهم:** `app.js` يُثبّت النطاق المشترك والأدوات، ثم تُحمَّل ملفات
التقرير بالترتيب أعلاه، وآخرها `report-print.js` الذي يستدعي `ADMHReport.boot()`
لتشغيل التطبيق. لا تغيّر الترتيب في `index.html`.

**ملاحظة:** لم يتغيّر أي منطق عند النقل — الكود منقول كما هو حرفياً.

## ملاحظات تقنية

- توليد ملف Word يتم **داخل المتصفح** بمكتبة `docx`، ولا يحتاج أي خادم.
- يجب استخدام `Packer.toBlob()` في المتصفح؛ فـ `toBuffer()` يفشل خارج Node.js.
- **لا جداول في ملف Word** (بطلب صريح): كل البيانات فقرات. لذلك لا تُستخدم
  `Table`/`TableCell` إطلاقاً في المولّد.
- تباعد الأسطر يُكتب صراحةً بـ `lineRule: auto` مع `line: 276`؛ فإغفال `lineRule`
  يجعل بعض العارضين يفسّره كضبط دقيق فيتضاعف التباعد ويزيد عدد الصفحات.
- كل ربط الأحداث يمرّ عبر `bindOn`/`bind` اللتين تتجاهلان العنصر المفقود.
  السبب: `.onclick =` على عنصر غير موجود يُطلق استثناءً يوقف الدالة كلها،
  فتتعطّل **كل** الأزرار التي تليه — وهذا ما حدث فعلاً وتم إصلاحه.
- قوائم الاقتراحات (`datalist`) معرّفة **خارج الجداول**، لأن إعادة رسم أي جدول
  كانت تمحوها فتختفي قائمة الصفة/المنصب من الحقول.
- إعدادات Firebase **مضمّنة في `sync.js`**. هذه المفاتيح عامة بطبيعتها في تطبيقات
  الويب، والحماية الفعلية من **قواعد أمان Firestore** و**Authorized domains**.
- عند دمج الإعدادات في المزامنة، **يُدفع الناتج المدموج لا القيم المحلية**؛ وإلا
  فإن جهازاً جديداً بلا إعدادات يطمس إعدادات السحابة.
- الحذف يُعلَّم بـ«شاهد قبر» (`_deleted`) لينتشر إلى الأجهزة الأخرى عند المزامنة.

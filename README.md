# نظام التقارير التفتيشية

نظام لإدخال بيانات **الزيارة التفتيشية وزيارات المتابعة** وتصدير تقرير **Word (.docx)** بقالب رسمي.

يعمل على **الحاسوب والهاتف**، و**بلا إنترنت**، وبلا خادم أو قاعدة بيانات.

---

## ما الذي يفعله

| المرحلة | الوصف |
|---|---|
| **إدخال البيانات** | نموذج عربي كامل للجانب **الإداري** فقط: بيانات المؤسسة، المسؤولون، الملاك، وحدة البصمة، الإجراءات، الملاحظات العامة، مواقف البصمة، السجلات الإدارية، التوصيات، التوقيعات |
| **نطاق التقرير** | تختار: **البصمة والسجلات** معاً، أو **البصمة فقط**، أو **السجلات فقط** — وتُخفى الأقسام غير المختارة |
| **مكتبة عبارات** | تقييمات جاهزة للسجلات وتوصيات متكررة مستخرجة من التقارير السابقة، بإملاء مصحّح |
| **معاينة** | عرض التقرير بشكل مطابق لملف Word قبل التصدير |
| **تصدير Word** | ملف `.docx` حقيقي بمقاس A4، اتجاه RTL، ترويسة رسمية، **فقرات فقط بلا أي جدول**، وترقيم صفحات |
| **الأرشيف** | حفظ واسترجاع وبحث، وتصدير/استيراد نسخة احتياطية بصيغة JSON |
| **المزامنة** | اختيارية — لمشاركة التقارير بين هاتفك وحاسوبك |

### ملاحظات على البنية

- الجانبان **الفني والهندسي غير مشمولين** — النظام للجانب الإداري فقط.
- ملف Word الناتج **لا يحتوي أي جدول**: كل البيانات (الملاك، السجلات، متابعة التوصيات) تُصاغ فقرات نصية.
- عنوان التقرير **يُولَّد تلقائياً** من نوع الزيارة + نوع المؤسسة + اسم المؤسسة + الجهة التابعة،
  ويتحدّث فور تغيير أي منها. وإن كتبته بيدك يحترم النظام كتابتك ولا يستبدلها.
- الملاك يحتوي سبع فئات جاهزة: الملاك، الأطباء، أطباء الأسنان، الصيادلة، تقني طبي، ممرضين، إداريين.
- كل سجل إداري يقبل **أكثر من تقييم جاهز** بنقرة، **بالإضافة** إلى تقييم تكتبه بيدك، ويُدمجان معاً.
- فئات المخالفة في مواقف البصمة (تغيب / عدم بصمة مغادرة / عدم بصمة دخول / عدم تأدية المفاجئة /
  عدم تأدية البصمتين) كلها بثلاثة حقول: العنوان الوظيفي، الاسم الثلاثي، ملاحظة.

## التشغيل

### محلياً (بلا إنترنت مطلقاً)

افتح `index.html` مباشرة بالنقر المزدوج. سيعمل كل شيء عدا التثبيت كتطبيق.

### عبر خادم محلي (لتثبيت التطبيق على الهاتف)

```bash
python -m http.server 8080
```

ثم افتح `http://localhost:8080`.

## النشر على Cloudflare Pages

### 1) ارفع المشروع إلى مستودع GitHub **خاص**

```bash
git init
git add .
git commit -m "نظام التقارير التفتيشية"
git branch -M main
git remote add origin https://github.com/<حسابك>/<المستودع>.git
git push -u origin main
```

### 2) اربط المستودع بـ Cloudflare Pages

1. سجّل الدخول إلى <https://dash.cloudflare.com> ← **Workers & Pages** ← **Create** ← **Pages** ← **Connect to Git**.
2. اختر المستودع الخاص. ستحتاج إلى منح Cloudflare صلاحية الوصول إلى مستودعاتك الخاصة.
3. إعدادات البناء:
   - **Framework preset**: `None`
   - **Build command**: *(اتركه فارغاً)*
   - **Build output directory**: `/`
4. اضغط **Save and Deploy**.

سيصبح الرابط بالشكل: `https://<اسم-المشروع>.pages.dev`

### 3) حماية الوصول (مهم)

الرابط عام افتراضياً. لتقييده على موظفي الدائرة:

**Cloudflare Access** ← **Zero Trust** ← **Access** ← **Applications** ← أضف تطبيقاً من نوع *Self-hosted*، وحدّد:
- النطاق: `اسم-المشروع.pages.dev`
- السياسة: البريد الإلكتروني للعاملين المصرّح لهم (OTP عبر البريد) أو نطاق بريد الدائرة.

هذا يمنع أي شخص خارج القائمة من فتح الموقع أصلاً.

### 4) ملاحظة على الخصوصية

الموقع **ثابت بالكامل**. لا يوجد خادم يستقبل البيانات، ولا قاعدة بيانات، ولا إرسال لأي معلومة.
كل بيانات التقارير تُخزَّن في متصفح المستخدم فقط (`localStorage`)، ولا تُرفع إلى Cloudflare إطلاقاً.

لذلك حتى مع استضافة مجانية، لا توجد بيانات موظفين على أي خادم خارجي.

**القيد المترتب على ذلك:** البيانات لا تتزامن بين الهاتف والحاسوب تلقائياً. للنقل بينهما استخدم
«تصدير كل الأرشيف (JSON)» ثم «استيراد» في الجهاز الآخر.

## التحقق بعد النشر

افتح `https://<موقعك>/check.html` — صفحة فحص تتحقق من:

1. **تشغيل النظام**: البروتوكول، التخزين المحلي، عامل الخدمة (العمل بلا إنترنت).
2. **المزامنة السحابية**: أدخل بريدك وكلمة المرور، وتختبر الصفحة الدخول وقراءة/كتابة
   Firestore فعلياً، وتخبرك بالسبب الدقيق إن فشلت — مع الخطوة المطلوبة في لوحة Firebase.

### الأخطاء الشائعة وحلولها

| ما تراه | السبب | الحل |
|---|---|---|
| «هذا النطاق غير مصرّح به في Firebase» | نطاق `pages.dev` غير مضاف | **Authentication** ← **Settings** ← **Authorized domains** ← **Add domain** ← أضف `your-project.pages.dev` |
| «تسجيل الدخول بالبريد وكلمة المرور غير مُفعَّل» | لم تُفعّل طريقة الدخول | **Authentication** ← **Sign-in method** ← فعّل **Email/Password** |
| «رفض الخادم العملية — قواعد أمان Firestore» | القواعد غير منشورة | **Firestore Database** ← **Rules** ← الصق القواعد أدناه ← **Publish** |
| «قاعدة بيانات Firestore غير موجودة» | لم تُنشئ القاعدة | **Build** ← **Firestore Database** ← **Create database** |
| صفحة «جارٍ التحقق» من Cloudflare تظهر دائماً | Access لا يتذكّر الجلسة | تأكد من إعداد سياسة Access، وأن المتصفح يسمح بالكوكيز |
| التعديلات لا تظهر على الموقع | Cloudflare لم يُعِد البناء | Pages ← آخر نشر ← **Retry deployment**، أو ادفع تعديلاً جديداً |

### ملاحظة مهمة على الخصوصية مع Zero Trust

لا تُدخل **الموظفين المُفتَّش عليهم** في سياسة Access إلا إذا كان ذلك مقصوداً — فمن يملك بريداً
في القائمة يستطيع فتح النظام وإدخال تقارير. اجعل القائمة على قدر من يحتاج الإدخال فعلاً.

وقواعد Firestore أدناه تعزل بيانات كل مستخدم بحسب `uid`، فلا يرى أحد تقارير غيره
حتى داخل نفس النظام.

## النسخ الاحتياطي

البيانات في متصفح الجهاز. **حذف بيانات المتصفح = فقدان التقارير.**

- صدّر ملف JSON من صفحة الأرشيف بانتظام.
- احفظ النسخة في مكان آمن (قرص خارجي أو مجلد مشترك).

التطبيق يحفظ **مسودة تلقائية** للتقرير الجاري العمل عليه، فلو أُغلق المتصفح بالخطأ لا يُفقد العمل.

## المزامنة السحابية (اختيارية)

لجعل التقارير تظهر على **الهاتف والحاسوب معاً**. التطبيق يعمل كاملاً بدونها.

### خطوات الإعداد (مرة واحدة فقط)

إعدادات Firebase **مضمّنة في الكود** (sync.js)، فلا تحتاج لصق أي مفاتيح.
يكفي تهيئة المشروع مرة واحدة:

1. افتح <https://console.firebase.google.com> واختر مشروعك
   dmh-inspection-reporting-sys.
2. **Build** ← **Authentication** ← **Get started** ← فعّل **Email/Password**.
3. **Build** ← **Firestore Database** ← **Create database**
   - اختر **Production mode**
   - اختر أقرب موقع جغرافي: me-west1 (أوروبا الغربية) هو الأقرب للعراق.
4. من تبويب **Rules** الصق القواعد أدناه ثم اضغط **Publish**. **هذه الخطوة إلزامية.**
5. في التطبيق: **الإعدادات** ← **المزامنة السحابية** ← أدخل بريداً وكلمة مرور
   (6 أحرف على الأقل) ← **تفعيل المزامنة**.

كرّر الخطوة 5 على الجهاز الآخر **بنفس البريد وكلمة المرور**، وستظهر التقارير تلقائياً.
إن لم يكن الحساب موجوداً سيُنشأ تلقائياً عند أول دخول.

> **بخصوص نطاقات النشر:** *.pages.dev و localhost مضافان تلقائياً في Firebase.
> إن نشرت على نطاق مخصص فأضفه في **Authentication** ← **Settings** ← **Authorized domains**.

### قواعد أمان Firestore (إلزامية)

الصقها كما هي. تمنع أي مستخدم من رؤية بيانات غيره:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
    // لا وصول لأي مسار آخر
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

### كيف تعمل المزامنة

| السلوك | التفصيل |
|---|---|
| **الاتجاه** | ثنائي: سحب ← دمج ← دفع. كل جهاز يرى تعديلات الآخرين. |
| **التعارض** | الأحدث يفوز بحسب `updatedAt`. التعديل الأقدم لا يطمس الأحدث. |
| **الحذف** | يُعلَّم السجل بـ«شاهد قبر» بدل حذفه فوراً، لينتشر الحذف إلى بقية الأجهزة. |
| **العمل بلا إنترنت** | كل شيء يُحفظ محلياً أولاً. عند عودة الاتصال اضغط «مزامنة الآن». |
| **الخصوصية** | كل البيانات في `users/{uid}/...` — لا يرى أحد بيانات غيره. القواعد تفرض ذلك على الخادم لا في التطبيق فقط. |
| **ما يُزامَن** | التقارير + الإعدادات (الترويسة والخط) + مكتبة العبارات. |

### تنبيهات مهمة

- **الخطوة الرابعة (Rules) ليست اختيارية.** بدونها إما تُرفض كل العمليات أو — إن
  تُركت في وضع الاختبار — تصبح بياناتك مكشوفة لأي شخص يملك رابط المشروع.
- التطبيق لا يُحمّل أي سكربت خارجي إلا بعد ضغطك «تفعيل المزامنة».
- عمل مشروع Firebase لا يعني أن وزارة الصحة وافقت على تخزين بيانات الموظفين على
  خوادم Google. راجع جهتك قبل إدخال بيانات حقيقية.
- الرابط العام للموقع محمي بـ Cloudflare Access، لكن Firebase مشروع منفصل وله
  ضبطه الأمني الخاص (القواعد + Authorized domains).

## ملاحظات تقنية

- توليد ملف Word يتم **داخل المتصفح** بمكتبة `docx`، ولا يحتاج أي خادم.
- يجب استخدام `Packer.toBlob()` في المتصفح؛ فـ `toBuffer()` يفشل خارج Node.js.
- **لا جداول في ملف Word** (بطلب صريح): كل البيانات فقرات. لذلك لا تُستخدم
  `Table`/`TableCell` إطلاقاً في المولّد.
- تباعد الأسطر يُكتب صراحةً بـ `lineRule: auto` مع `line: 276`؛ فإغفال `lineRule`
  يجعل بعض العارضين يفسّره كضبط دقيق فيتضاعف التباعد ويزيد عدد الصفحات.
- كل ربط الأحداث يمرّ عبر `bindOn`/`bind` اللتين تتجاهلان العنصر المفقود.
  السبب: `.onclick =` على عنصر غير موجود يُطلق استثناءً يوقف الدالة كلها،
  فتتعطّل **كل** الأزرار التي تليه — وهذا ما حدث فعلاً وتم إصلاحه.
- قوائم الاقتراحات (`datalist`) معرّفة **خارج الجداول**، لأن إعادة رسم أي جدول
  كانت تمحوها فتختفي قائمة الصفة/المنصب من الحقول.
- إعدادات Firebase **مضمّنة في `sync.js`**. هذه المفاتيح عامة بطبيعتها في تطبيقات
  الويب، والحماية الفعلية من **قواعد أمان Firestore** و**Authorized domains**.
- عند دمج الإعدادات في المزامنة، **يُدفع الناتج المدموج لا القيم المحلية**؛ وإلا
  فإن جهازاً جديداً بلا إعدادات يطمس إعدادات السحابة.
- الحذف يُعلَّم بـ«شاهد قبر» (`_deleted`) لينتشر إلى الأجهزة الأخرى عند المزامنة.
